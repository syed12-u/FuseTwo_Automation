## New defects found
**1. Add Text Link accepts whitespace-only Text Link Content (low severity, client validation).**
- Steps: Creatives → Add Text Link → Program `Test4302026`, Campaign `Test4302026` →
  type five spaces into Text Link Content → Next.
- Expected: field flagged "This field is required." (value trimmed), wizard stays on step 1.
- Actual: field reads `aria-invalid=false`, wizard advances to Targeting (Visible / Invisible /
  Visible to selected, Save enabled). Back shows the 5-space value intact.
- Not verified server-side: Save was not clicked, because a blank creative cannot be deleted from
  the UI and would be left behind. Reproduced on the discovery run only (see Flaky/blocked).
- Evidence: `test-results/daily-explorer/Creatives-testDailyExplore-8a1dd-mp-the-Add-Text-Link-wizard-chromium/05-after-next-whitespace.png`
  (step 2 rendered) and `.../05b-after-back.png` (5-space value kept). Same-day only: the folder
  is regenerated by the next explorer run.
- Suggested bug title: "Creatives: Add Text Link treats whitespace-only Text Link Content as valid and
  reaches Targeting".
